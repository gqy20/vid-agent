# EP02 B 站发布物料

## 标题

git add 到底做了什么？Git 的三层一次讲清

## 封面文字

主标题：

```text
文件不会直接进 commit
```

副标题：

```text
先 add，再 commit
```

1. 简介

很多人把 git add 当成保存，把 git commit 当成再保存一次。

这一集把中间被跳过的东西补上：文件从被修改到被提交，会经过工作区、暂存区、仓库三层。git add 把当前内容放进暂存区，git commit 从暂存区读取并写进仓库历史。

把这三层立起来之后，git status 看到的 staged / unstaged、add 之后继续改会发生什么，就都能对上号了。

2. 你会学到

- 工作区、暂存区、仓库分别保存什么
- git add 把内容放到哪一层
- git commit 从哪一层读取
- 为什么 add 之后继续改，同一个文件会同时有已暂存和未暂存两种变化
- git status 在三层模型里看的是什么

3. 时间轴

00:00 文件不是直接进入 commit
00:12 工作区 / 暂存区 / 仓库 三层
00:38 修改先发生在工作区
01:08 git add 暂存当前内容
01:44 add 之后再改：staged 与 unstaged
02:14 git commit 从暂存区写入仓库
02:44 收束：修改、暂存、提交

4. 适合谁

- 会 add / commit，但不懂中间发生了什么的人
- 被 staged / unstaged 搞晕的人
- 想从底层状态模型理解 Git 的人
