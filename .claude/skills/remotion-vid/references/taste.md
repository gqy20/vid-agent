# Remotion 视频品味标准

这份文档用于约束 Remotion 成片的审美和叙事质量。它不是灵感板,而是交付标准:每条视频都必须能通过这里的检查,否则不要进入 final render。

## 核心判断

一条高级的 Remotion 产品视频应该像一篇有剪辑节奏的产品备忘录:先提出判断,再给证据,最后落到动作。它不应该像功能清单、官网首屏轮播、CLI 帮助页或字幕版 PPT。

最低标准:

- 每个场景只回答一个问题:异常是什么、证据在哪、下一步做什么。
- 画面必须提供文本以外的信息。屏幕上已有完整句子时,不要再用字幕复述。
- 使用真实产品截图、真实数据、真实命令。不要用虚构 KPI、假终端输出、假 dashboard。
- 动效必须服务定位、层级、转场或注意力引导。装饰性飘动、随机粒子、光斑、彩色胶囊默认视为廉价。
- 字体、颜色、截图、音频、节奏要像同一个品牌系统,不是素材拼贴。

## Awwwards 可借鉴什么

Awwwards 的价值不是照搬夸张网页特效,而是学习它对叙事、交互和视觉层级的要求。

可借鉴:

- **编辑感**: 大标题有明确断行,留白大胆,每屏有主从关系。
- **运动有目的**: 动画用于引导视线、建立空间关系、解释状态变化。
- **沉浸但克制**: 可以有 3D、WebGL、Lottie、滚动叙事,但每种技术都必须强化主题。
- **内容和创意绑定**: 一个漂亮镜头必须同时推进故事,不能只是炫技。
- **可用性权重**: Awwwards 评估不只看创意,还看 usability 和 content。产品视频同理,看不懂就是失败。

不要借鉴:

- 首屏巨大空洞 slogan。
- 无信息密度的全屏渐变、抽象球体、漂浮卡片。
- 每一屏都在做 portfolio 式炫技转场。
- 过度视差导致用户看不清产品。

## 叙事结构

产品诊断类视频推荐使用 6-8 个短场景,总长 45-70 秒:

1. **异常现场**: 用真实数据开场,不先讲品牌。
2. **第一条判断**: 给出最强 finding,如失败率、慢调用、成本异常。
3. **证据链**: 从总览进入 failure / command / token / session / tool drilldown。
4. **归因**: 说明问题落在哪个工具、命令、模型、会话或项目。
5. **动作**: 展示 CLI 命令、JSON 输出、配置文件或修复建议。
6. **工作流**: 说明它如何进入日常开发流程。
7. **品牌收束**: 最后再出现产品名和仓库地址。

禁用结构:

- 先 logo,再 slogan,再功能点罗列。
- 每屏都是同一句旁白的不同排版。
- 展示 dashboard,但旁白和标题说的是另一个功能。
- 一开始解释背景知识超过 8 秒。

## 文案和字幕

屏幕文案要承担剪辑功能,不是旁白逐字稿。

规则:

- 标题最多两行,每行 6-12 个汉字或 3-7 个英文词。
- 正文最多 2-3 行,只补充画面看不出的判断。
- 若画面已有大标题和产品截图,默认不加底部字幕。
- 需要配音时,旁白说因果和判断;画面文字放数字、命令、对象名。
- 不要在同一帧里同时出现:大标题、长正文、字幕条、截图内大段文字、徽章说明。

重复信息判定:

- 画面标题是“把失败归因到具体命令”,字幕也说“失败可以归因到具体命令” → 删除字幕。
- 截图表格已经显示 `test 失败率 39.4%`,旁边徽章再强调一次可以;字幕再读一遍不可以。
- 旁白说“成本落到模型和会话”,画面展示 token/model/session 表格 → 合格。

## 字体

字体决定质感。默认系统 sans 或奇怪 nerd font 会直接拉低成片。

推荐栈:

- 中文标题: `Noto Serif CJK SC`, `Source Han Serif SC`, `Songti SC`
- 中文正文: `Noto Sans CJK SC`, `Source Han Sans SC`, `Sarasa UI SC`
- 英文标题: `Inter Display`, `Neue Haas Grotesk`, `Geist`, `IBM Plex Sans`
- 代码/命令: `JetBrains Mono`, `IBM Plex Mono`, `SF Mono`

使用规则:

- 标题可以用 serif,正文用 sans,命令用 mono。不要全片只用一种字体。
- 中文标题行高 1.08-1.18;正文行高 1.42-1.58。
- 不要负字距。视频压缩后负字距会显脏。
- 1080p 下左侧叙事标题建议 52-64px;全屏 hero 标题 76-96px;正文 26-34px。
- 字体必须本地可用。渲染前用 `fc-list` 确认,避免 fallback。

## 色彩

高级产品视频不靠高饱和渐变取胜。先确定产品气质,再定色。

推荐策略:

- 背景使用近黑、暖灰、纸白、深墨绿、冷灰蓝等低噪声基底。
- 主色只用于状态和注意力,不要铺满全片。
- 危险/失败用红或橙,成本用琥珀,成功用低饱和绿。
- 截图本身已经很亮时,外部背景要压暗,让截图成为主体。

禁用:

- 紫蓝霓虹渐变作为默认背景。
- 多个发光圆球或 bokeh blob。
- 所有卡片、标签、线条都在同一 hue 上做深浅变化。
- 为了“科技感”把真实 dashboard 染成不可读的深色。

## 布局

优先用电影式构图,不要照搬网页 section。

常用布局:

- **左判断,右证据**: 左侧标题和解释,右侧真实截图或数据面板。
- **全屏证据**: 适合关键 dashboard、代码 diff、流程图。
- **中心命令**: 适合 CTA 或 CLI workflow。
- **分层叠加**: 截图为底,用 1-2 个 badge 标注重点。

约束:

- 1920x1080 安全边距: 左右至少 96px,上下至少 80px。
- 一帧最多 1 个主视觉、1 个标题组、1 个强调 badge。
- 卡片圆角保持 8-16px;不要卡片套卡片。
- 截图必须有稳定宽高和 `overflow: hidden`;避免入场时布局跳动。
- 不要把真实产品缩得太小。观众要能看出它是真的。

## 动效

Remotion 动效要像剪辑,不是网页 hover demo。

默认参数:

- 入场: 12-20 帧,`Easing.bezier(0.16, 1, 0.3, 1)`。
- 出场: 8-14 帧,快速淡出或轻微位移。
- 场景转场: 10-18 帧 fade,少量 slide。不要每个场景换一种转场。
- 截图可做 1.0 → 1.025 的慢 zoom,但整段不应漂移过多。
- 重要数字可以 stagger,每项间隔 4-8 帧。

动效目的:

- 入场建立层级。
- 转场表达“从总览到下钻”。
- badge 定位证据。
- 轻微 parallax 增加画面生命力。

禁用:

- 元素无理由弹跳。
- 线性匀速移动。
- 纯装饰粒子、流光、扫描线覆盖真实数据。
- 每个字逐字 opacity 跳出。

## Lottie 使用边界

Lottie 适合作为精致的微动效资产,不是整片动效系统。

适合:

- 空状态、加载状态、轻量品牌符号。
- 图标级转场,如 warning、check、search、flow。
- After Effects 里做好的矢量标识动画。
- 需要跨项目复用的小资产。

不适合:

- 关键产品截图的主要运动。
- 大面积背景装饰。
- 需要逐帧精确跟 Remotion 时间线同步的复杂叙事。
- 带复杂 expression 且无法稳定渲染的 AE 导出。

Remotion 使用建议:

- 安装 `@remotion/lottie` 和 `lottie-web`。
- Lottie JSON 放 `public/`,用 `staticFile()` + `fetch()` + `delayRender()` 加载。
- 用 Remotion frame 控制出现时机;不要依赖浏览器 CSS animation。
- 每个 Lottie 必须渲 still 抽帧检查,确认无闪烁、无空帧、无错位。
- 如果 Lottie 只是“让画面动起来”,删掉。

## 产品截图

截图是产品视频最重要的证据资产。

采集规则:

- 从真实服务或真实 Storybook 采集,不要手画假 UI。
- 采集前设置固定 viewport,推荐 1280x720 或 1440x900。
- 需要下钻时,截图必须真的处于对应 tab/filter/scroll 位置。
- 截图中不需要看的区域要裁掉,不要把整页缩成小字墙。
- 高亮只做 1-2 个重点,不要到处画框。

截图进入 Remotion 前:

- 检查是否含敏感路径、token、用户名、密钥。
- 检查裁切顶部/底部是否有半截卡片。
- 检查缩放后 1080p 是否仍可读。

## 音频

音频不能弥补画面叙事失败。

规则:

- 无配音时,画面文案必须能独立讲完故事。
- 有配音时,屏幕文字减少 30-50%。
- BGM 音量峰值通常 0.12-0.18;不能盖过配音。
- 结尾要淡出,不要硬切。
- 不要为了“高级”使用过度史诗或广告感鼓点。

## 交付前检查

每条 Remotion 视频 final render 前必须完成:

- `pnpm typecheck` 通过。
- 每个场景至少渲 1 张 still 并人工查看。
- 检查标题断行、正文溢出、截图裁切、徽章遮挡。
- 检查画面文字和字幕/旁白是否重复。
- 检查真实数据是否来自当前产品或文档。
- 检查字体是否命中预期本地字体。
- 检查 3 个时间点:开头 5 秒是否进入主题,中段是否有证据推进,结尾是否有明确动作。
- `ffprobe` 校验 final mp4 的 duration、fps、分辨率、音频轨。

如果只能用一句话评价:好的 Remotion 产品视频不是“更炫”,而是每 5 秒都让观众更接近一个可信判断。
