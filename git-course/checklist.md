# Git Course 通用检查清单

本清单补充仓库级 [`课程视频统一生产规范`](../docs/course-production.md)，只增加 Git 教学、Git 状态、语义色、终端和课程包装的检查项。共享 Candidate、SHA、Current 和 Release 门禁不得在本清单中放宽。

本清单用于每一集从脚本定稿到发布封装的统一验收。它只回答“当前内容能否进入下一阶段”，不替代以下文档：

- `workflow.md`：说明如何生产。
- `episodes/<episode-id>.json 的 content.qualityMarkdown`：记录本集特有问题、人工判断和修复历史。
- `episodes/<episode-id>.json 的 release.checklistMarkdown`：检查平台上传物料。

使用方式：开发中执行“每次修改必查”，完成单个 scene 后执行“Scene 验收”，整集确认后执行“成片与发布验收”。发现阻断项时先修复，不带着已知问题进入下一阶段。

## 一、每次修改必查

### 改动范围

- [ ] 修改前已查看工作区状态和相关 diff，没有覆盖其他人的在途改动。
- [ ] 只修改当前分集、共享组件、相关脚本或文档，没有顺手重构无关区域。
- [ ] 可维护内容位于 `git-course/` 或源码目录，生成媒体没有误加入 Git。
- [ ] 临时抽帧和试渲染位于 `tmp/`，检查完成后会清理。

### 基础校验

- [ ] `pnpm --dir remotion git-course:validate` 通过。
- [ ] 修改 `episode JSON` 后已运行 `pnpm --dir remotion git-course:generate`。
- [ ] `pnpm --dir remotion typecheck` 通过。
- [ ] 修改共享布局、Git 图、状态流、终端或字幕组件后，`pnpm --dir remotion git-course:lab:audit` 严格模式通过。
- [ ] 共享视觉改动已在 Component Lab 的正常输入和 stress case 中检查，并 preview 至少一个真实受影响 scene。
- [ ] 修改过的 Shell、Node 或 Python 脚本已完成对应语法检查。
- [ ] `git diff --check` 通过。

## 二、教学与脚本门禁

### 本集目标

- [ ] 本集只解决一个明确的核心误解或心智模型问题。
- [ ] 开头能快速提出问题，不先堆背景知识。
- [ ] 旁白以问题、观察、证据和共同推演推进，没有连续使用“你必须”“你要记住”“正确做法就是”等说教式句型。
- [ ] 每个提问都推动当前教学动作，并在同一 scene 或紧邻 scene 得到可见证据，不用空泛反问拖延结论。
- [ ] 结尾能用一至三条短结论复述本集模型。
- [ ] 结尾把结论收束为可复用的判断问题或心智模型，不要求观众背诵命令清单。
- [ ] 内容自然落在约 2.5–5 分钟；不为满足固定秒数增加重复解释或删除必要过程。
- [ ] 超出本集范围的概念已明确留给后续集，不在当前画面顺带展开。

### Scene 设计

- [ ] 每个 scene 只承担一个教学动作：提问、执行命令、观察变化、解释原理或总结。
- [ ] 每个命令都写清楚执行前状态、动作对象和执行后状态。
- [ ] 需要观众理解的状态变化有动画过程，不直接跳到最终结果。
- [ ] episode JSON 中的教学目标、scene、旁白与实际画面表达一致。
- [ ] 复杂关系已用可复用的 Remotion 状态模型实现，没有散落在 episode 中的临时 SVG，也没有新增 Manim 集成。

### Git 事实与术语

- [ ] 术语符合 `terminology.md`，同一概念没有混用多个名称。
- [ ] Working Tree、Index、Repository、HEAD、branch、commit 的关系准确。
- [ ] `git add` 表达为把当前内容写入 Index，而不是“把文件加入项目”。
- [ ] `git commit` 表达为读取 Index 生成提交，而不是保存 Working Tree 当前内容。
- [ ] branch 表达为可移动指针，HEAD 的附着或 detached 状态表达准确。
- [ ] merge、rebase、reset、restore、revert 的动作对象与后果没有混淆。

### 远程协作、冲突与恢复

- [ ] remote-tracking ref 明确画在本地仓库内，表示最近一次通信后本地保存的远端状态，没有画成服务器上的 branch 本身。
- [ ] `fetch` 表达为取得对象并按 refspec 更新本地记录；没有自动移动当前本地 branch，也没有自动修改 Index 或 Working Tree。
- [ ] `pull` 表达为 fetch 后再整合，演示命令显式指定 `--ff-only`、`--rebase` 或 `--no-rebase`；没有把机器配置或 Git 版本的默认策略写成普遍事实。
- [ ] `push` 表达为发送所需对象并请求更新远端 ref，不是上传 Working Tree；成功、客户端拒绝、远端拒绝和网络失败没有混成同一种结果。
- [ ] ahead/behind 的比较对象是当前 branch 与本地 upstream ref；需要声称服务器最新状态时已经先 fetch，没有把旧计数说成实时查询结果。
- [ ] non-fast-forward 用旧 ref 是否为新目标祖先来判断；普通协作分叉优先 fetch 后 merge/rebase，没有用盲目 `--force` 掩盖未整合历史。
- [ ] 冲突画面区分 Working Tree 中的标记与 Index 中的 unmerged entries；merge 的 stage 1/2/3 分别对应 base、ours、theirs。
- [ ] `git add` 之后，多阶段未合并条目确实收束为普通 stage 0；旁白进入 continue/commit 前，终端和状态模型均已证明不再存在 unmerged paths。
- [ ] rebase 场景没有机械沿用 merge 视角的 ours/theirs 标签；`--continue`、`--skip`、`--abort` 与当前操作类型对应。
- [ ] reflog 明确限定为本地、会过期的 ref 更新记录；恢复时先验证旧对象并创建救援 branch，没有把 reflog 说成服务器历史或永久备份。

## 三、Scene 验收

每个 scene 完成后单独渲染，至少检查开头、动作前、动作中、动作完成和结尾五类帧。动画较复杂时增加逐帧或连续抽帧检查。

### 构图与信息层级

- [ ] 当前主角明确，终端、状态板、代码、Git 图和字幕没有同时争夺注意力。
- [ ] 问题镜头使用居中结构；命令镜头优先终端聚焦；状态镜头让结果模型接管主视觉。
- [ ] 正文场景大标题统一使用 `SceneTitle`：60px、单行、最多 20 个全角等效显示单位；超过限制先精简文案，不缩小字号或依赖浏览器自动换行。
- [ ] 主标题、章节标题、卡片标题没有裁切、缺字或异常换行；`data-audit-single-line` 没有报告真实字体宽度溢出。
- [ ] 长路径、长 branch 名和双语状态文字在真实卡片宽度内正确换行，没有被 `overflow: hidden` 静默裁掉。
- [ ] 中英文混排、等宽字体、行高和字重在实际编码帧中清晰可读。
- [ ] 画面关系箭头统一使用真正的 `→` 字形，不使用 ASCII `->` 拼接箭头。
- [ ] 重要英文标签不小于其下方辅助中文的视觉权重。
- [ ] active、计数、状态标签与对应标题在同一视觉组内，对齐稳定。

### 对齐与遮挡

- [ ] 元素以实际可见边界对齐，不依赖过期的硬编码估算。
- [ ] 静态位置来自确定性舞台或明确 bounds；没有用动画 transform 修复本应由布局解决的偏移。
- [ ] 自动审查没有发现画布越界、安全区越界、阻断性重叠、过近元素或幽灵透明度。
- [ ] 箭头、虚线和连接线确实连接语义对象，起点、终点和方向正确。
- [ ] Git 图按“历史边 / ref 连接线在下，commit 节点在上”的顺序绘制；任何连接线都没有压住节点填充或描边。
- [ ] 连接线按节点的实际半径、描边和局部缩放计算，并保留统一的受控 underlap；不能只与圆圈外沿相切，必须由顶层 commit 节点覆盖连接线末端，避免抗锯齿留缝。
- [ ] 放大 commit 节点时，历史边端点、branch/ref 连接线、标签偏移和周围说明位置已同步更新，不只放大圆圈本身。
- [ ] 新增或调整 branch/ref 标签时使用 `placement="above|below"` 和共享 `refVisualGap`，不再用任意 `y` 模拟间距；只有历史兼容场景可以暂时保留显式坐标。
- [ ] merge commit 对每个 parent 只保留一条父边；语义强调通过修改原父边的颜色或样式完成，没有再叠一条近似路径形成“四条线”。
- [ ] 箭头与文件名、标题、状态标签、边框和其他线条没有重叠。
- [ ] 卡片之间的箭头尖端与边框保留可见间距，没有把箭头尖端压在 Snapshot、代码卡或状态框边界上。
- [ ] 文件卡、代码卡、终端和状态板之间留有明确间距，不产生“属于哪个容器”的歧义。
- [ ] 字幕、说明文字和播放器安全区不遮挡主视觉。
- [ ] 终端下半部分若长期为空，已通过裁切或重新构图减少无效占位。

### 状态板与总结镜头

- [ ] Working Tree、Index、Repository 状态板的高度与实际内容量匹配；只有一行内容时使用紧凑布局，不保留大面积空框。
- [ ] 状态板缩短后同步提高标题、状态标签和文件文字的可读性，没有把“紧凑”做成小字。
- [ ] 旁白从 unresolved 进入 resolved、commit 或 abort 时，画面状态也按相同顺序变化；不得让静止的 unmerged 面板覆盖后续处理步骤。
- [ ] 总结镜头的图形、分栏标题、描述和底部字幕形成清楚的纵向节奏；局部放大图形后已重新调整描述位置和字幕安全距离。
- [ ] 总结镜头复用前文的 Git 几何语义，只调整当前镜头需要的视觉比例，不把放大参数反向污染其他 scene。

### 颜色与强调

- [ ] `main`、`feature`、`HEAD`、Working Tree、Index、Repository 和 conflict 只使用各自语义色。
- [ ] Working Tree 的修改高亮没有误用接近 Index 的琥珀色。
- [ ] 高亮落在真正需要观众记住的关键词或状态上。
- [ ] 高亮进入一次、解释变化后回到稳定样式，没有无意义闪烁、脉冲或循环。
- [ ] 普通说明使用中性色，不挪用 Git 状态色做装饰。

### 终端

- [ ] 使用 `git-course-lab` 真实录制资产，没有在 episode 中临时仿造终端。
- [ ] 命令输入阶段终端独占或接近独占；命令完成后终端降权为证据或退出。
- [ ] 终端标题、字体、字号、行距、光标、提示符和配色符合课程统一主题。
- [ ] 光标只能来自真实录制；录制隐藏光标时只保留 `>` 提示符，不使用 FFmpeg 或 episode 叠加人工竖线。
- [ ] `>`、命令和输出在编码后 MP4 中仍清楚，没有因缩放变细或模糊。
- [ ] 终端裁切保留标题栏、完整命令与必要输出，没有裁掉语义信息。
- [ ] hold frame 与录屏最终状态一致，没有提前跳到结果或闪回空帧。
- [ ] 一个录屏只解释一个命令结果；多条命令使用独立真实录屏和共享 cue 调度，没有在同一视口持续追加输出。
- [ ] 每条关键输出从相关旁白开始前后可见，并至少保持到对应字幕结束后 `0.5s`，解释完成前没有滚出视口。
- [ ] 没有用全局慢放代替语义停顿；打字速度、结果保持和 scene 切换分别受控。
- [ ] 独立录屏切换没有长时间停在空提示符；如使用 `startFromFrame`，完整命令和真实输出仍然可见。
- [ ] 录屏中出现的 commit 使用固定 author/committer date；重复录制不会因为时间变化生成新的短 hash。

### 动画与节奏

- [ ] 命令、状态变化和旁白因果顺序一致。
- [ ] 过渡期间没有近似空白帧，也没有旧画面与新画面形成半透明残影。
- [ ] 移动对象到达目标后正确并入目标状态，不留下含义不明的浮动副本。
- [ ] 运动结束后有足够观察时间，但没有长时间静止重复同一信息。
- [ ] 淡入淡出、缩放和位移服务于状态变化，不作为装饰。

## 四、音频与字幕门禁

### 源文件与时间窗

- [ ] 可维护旁白位于 `git-course/episodes/<episode-id>.json 的 scenes[].narration`。
- [ ] 每个 scene 有对应 `.txt`，并在 `manifest.tsv` 中按相同顺序出现。
- [ ] manifest 的旁白进入时间和 scene 结束时间与 `episode JSON` 一致。
- [ ] 每段规范化人声在对应 scene 结束前完成，没有跨段。
- [ ] `alignment.md` 记录必要的人工同步判断与例外。

### TTS 与人声

- [ ] 同一集固定使用 `speech-2.8-hd`、`Chinese (Mandarin)_Gentleman`、`zh`、`1.25`，或完整记录统一替代配置。
- [ ] 文稿使用短句和显式停顿标记，概念切换处没有连读。
- [ ] 已试听专有名词、Git 命令、英文缩写和版本号的发音。
- [ ] 每段 `_norm.mp3` 约为 `-20 LUFS`，峰值约为 `-3 dBFS`，段间响度差尽量小于 1 LU。
- [ ] 人声没有削波、爆音、异常呼吸声、语气标签误读或明显合成瑕疵。

### SRT 与字幕

- [ ] 每份 SRT 已检查，`<#...#>` 停顿标记没有泄漏成文字。
- [ ] 解说字幕维护在 `episode JSON` 的 `scenes[].captions`，并与生成后的实际 SRT 逐 cue 同文同时间；React 只负责渲染，不在 episode 组件里另写一套字幕时间线。
- [ ] SRT 使用旁白停顿标记对应的真实音频静音边界生成；句子数与内部停顿数不能一一对应时必须阻断，不允许按 cue 数量机械摊分文字。
- [ ] 每条字幕对应一条旁白短句；字幕正文与实际解说一致，只按课程约定清理句尾标点，不另写概括性复述。
- [ ] 句尾标点清理符合课程约定，问号和必要冒号得到保留。
- [ ] 画面内 `SceneCaption`、`QuestionCaption` 和说明标签的句尾不使用句号；保留问号和必要冒号。
- [ ] 同一时刻尽量只显示一条字幕；两行字幕确有必要且不会遮挡画面。
- [ ] 字幕跟随解说提供完整理解路径，但画面标题、代码和状态板不再额外复制同一句长文案。
- [ ] 长 scene 的字幕连续覆盖实际旁白，没有只在 scene 末尾放一句总结让初学者自行补全过程。

### 字幕、解说与画面一致性

- [ ] 一致性核对使用生成后的 `_norm.mp3` 和实际 SRT cue，不只参考 episode JSON 中的旁白草稿或预计时长。
- [ ] 已把 `voiceStart + SRT cue` 换算为 scene 内实际出声时间，并逐句对照对应的动画状态、命令、节点、卡片和状态板。
- [ ] 每条解说字幕的正文和时间与同一时刻实际播放的旁白一致；没有字幕仍讲祖先关系而解说已经进入命令，也没有字幕提前进入下一教学阶段。
- [ ] 解说提到的对象在同一时刻已经出现或正在进入；画面没有提前展示 M1、resolved、commit 或 abort 等尚未解释的结果。
- [ ] 所有字幕 cue 都检查过中点帧；字幕切换点还检查了前后帧，不能用“中点没有遮挡”代替时间同步检查。
- [ ] scene 结束余量不能只满足数学上大于零；旁白尾部余量小于 `0.5s` 时已列为人工复核项，确认编码和边界切换不会截字或听感过紧。
- [ ] 从上一 scene 人声结束到下一 scene 人声开始的实际间隔保持在 `1–2s`；最后一段到正片结束也保持 `1–2s`，除非 episode JSON 明确记录教学例外。
- [ ] 无声观察区只保留与刚结束解说一致的复盘信息，不在静音阶段突然引入 tree、merge commit 或下一步命令等新概念。

### BGM 与混音

- [ ] 优先复用课程统一 BGM，当前约定音量为 `0.05`。
- [ ] BGM 循环并裁切至正片完整时长，后半段没有意外静音。
- [ ] 不使用 sidechain ducking，背景音乐音量保持稳定。
- [ ] `voiceover-aligned.m4a` 与 `mix.m4a` 时长和正片一致。
- [ ] 戴耳机与普通扬声器各试听一次，人声均能稳定压过 BGM。

## 五、整集成片验收

### 文件与自动检查

- [ ] 修复阶段的分段预览已更新到 `tmp/preview/scenes/`，命名为 `01_scene_id.mp4` 形式，并由 manifest 记录 fingerprint 与 SHA。
- [ ] preview 是 cache 的 hardlink/兼容复制视图，没有被当作第二套长期缓存；过期 preview 已从 manifest 和目录中清理。
- [ ] `current/` 不保存 scene preview；分段只保留在 cache 与可重建的 `tmp/preview/scenes/`。
- [ ] build 音频先生成在 `tmp/build/candidate/audio/`；approve/promote 前没有改写 `current/audio/`。
- [ ] 当前正片已覆盖 `current/<episode-id>.mp4`，没有创建 `new`、`v2` 或 `final-final`。
- [ ] `current/` 下没有 `final/` 子目录；历史成片如需保留已移入 `tmp/legacy-final/`。
- [ ] main 视频为 1920×1080、30fps，视频与音频流均存在。
- [ ] 正片时长与 `episode JSON` 总时长一致，音画结尾没有被 `-shortest` 意外截断。
- [ ] 所有可生成 MP4、音频、SRT、抽帧和临时审查文件均被 `.gitignore` 正确排除。
- [ ] 权威 audit 机器未失败后，成功 task 的重复 MP4 和工作目录已清理；失败任务证据仍可用于排查。

### 连续观看

- [ ] 从头到尾完整观看一次，不只依赖静态抽帧。
- [ ] scene 边界没有黑帧、闪帧、重复帧、音频断裂或 DTS/PTS 异常表现。
- [ ] 旁白在对应信息出现后或同时进入，没有提前解释尚未出现的画面。
- [ ] 已逐 scene 记录“实际 SRT / 解说字幕 → 画面状态”的一致性结论；结构合法、字幕不遮挡和语义同步分别检查，不能互相替代。
- [ ] 相邻 scene 的信息密度和节奏衔接自然。
- [ ] 全片语义色、字体、标题栏、字幕和终端风格一致。
- [ ] 结尾回扣本集问题，并自然连接下一集，不使用重型预告板。

### 重点抽帧

- [ ] `tmp/build/audit/main/manifest.json` 中连续采样为 `2fps`，实际帧数与预期帧数一致。

## 阻断项

出现以下任一情况时，不进入发布封装：

- Git 状态变化或命令语义错误。
- Git 图的连线数量、端点、方向或图层顺序会让观众误判 parent、branch 或 commit 关系。
- 标题、字幕、文件名或关键状态被裁切或遮挡。
- 语义色混用，可能让观众误判对象。
- 旁白跨 scene、实际 SRT 与教学字幕/画面状态错位，或 SRT 泄漏停顿标记。
- 解说已经进入 resolved、commit 或 abort，但画面仍停在 unresolved 等旧状态。
- 编码后视频出现黑帧、闪帧、异常重复帧或缺失音轨。
- 当前正片路径、时长或分辨率不符合约定。
